# 仓库任务与 RFID 槽位记录

> RFID 回退修订：圆盘机、绕桩、阶梯恢复原来的有效 UID 确认与转盘调度，块数据仅用于附加记录。

## 当前流程

阶梯完成 → G3 → 后退 100 mm → 固定方向左移 1500 mm，同时逆时针转 180° → 停稳 → 后退 200 mm → 向右灰度找线（最多 50 秒）→ 停稳 → 仓库：

| 点位 | 到达方式 | 按顺序查找的编号 | 放置动作 |
| --- | --- | --- | --- |
| 第一列 | 找线结束后后退 200 mm | 11、21、31 | G109、G110、G111 |
| 第二列 | 再后退 200 mm | 12、22、32 | G109、G110、G111 |
| 第三列 | 再后退 200 mm | 13、23、33 | G109、G110、G111 |

每一行先查库存，有球才将其槽位转到取球口，转位结束后执行对应动作组。动作组完成回包后，该槽记为空。没有采集到的编号跳过动作组，仍走完三个列点位。第三列处理完才报告 `PATH_DONE`（step=13），没有第四次后退。

G109/G110/G111 必须已保存在舵控板中，分别包含“取球 → 放到第一/二/三行 → 手臂返回”。这些动作组自身不要额外转动储球转盘，转位由主控统一管理。

## 读卡器与卡数据

读卡器使用自动上传“卡号＋块 1 数据”，地址 0x20。按手册 V1.0.5，成功回包为 28 字节：

```text
04 1C 04 20 00 [卡类型 2 字节] [UID 4 字节] [块数据 16 字节] [校验 1 字节]
```

UID 位于偏移 7～10，块数据位于偏移 11～26；全部 28 字节异或应为 `FF`。程序检查包头、长度、命令、地址、状态与校验。沿用原来的 UID 判定：12 字节卡号帧（自动读卡号或 A1 回包）和 28 字节组合帧均可确认夹取，按原逻辑驱动转盘；仅块数据帧不能确认夹取。

块 1 写入 **16 个相同的十六进制字节**，如：

```text
23 23 23 23 23 23 23 23 23 23 23 23 23 23 23 23
```

表示第二行第三列。合法值仅为 `11 12 13 21 22 23 31 32 33`，高半字节为行、低半字节为列，不是 ASCII 字符串。程序不发送读块命令，也不会在启动时重写读卡器配置。

读卡应保持“**一直读/连续读取并上传**”：采集窗口在夹取动作完成之后才打开，窗口之前的数据会被丢弃。若只在卡首次进入时上传一次，可能在窗口打开前就发完，导致等待 RFID 确认。块 1 的读取权限和密钥也需正确。

## 12 槽记录方式

- 上电时必须为空盘，并将一个槽对准存取球口；该槽定义为逻辑槽 0。存球口和取球口是同一位置。
- 圆盘机、绕桩、阶梯共用一份 RAM 库存，记录 UID、目的编号和槽位。每次有效采集先登记当前槽，然后按原方向转一个槽。
- 读到有效新 UID 后立即按原逻辑发送对应的 `DISC_RFID_OK`、`PILLAR_RFID_OK` 或 `STAIR_RFID_OK`，不再等待转盘结束。转盘仍按累计新 UID 数逐次转位；重复 UID 不重复计数。
- 附加记录按采集顺序保存 UID、目标编号和逻辑槽位。合法组合帧可记录目标编号；没有块数据、块数据非法或编号冲突时仍放行前三个任务，将该槽目标编号记为未知（0），保留诊断。仓库只放置已知编号的球；若最后仍有未知球留在盘中，报告 PATH_ERROR，不虚报全部入库成功。
- 仓库找球比较正反两个方向的槽数，按较短路径逐槽转位，最多 6 槽；半圈等距时取反方向。到目标槽才执行动作组。
- 沿用原电机报文：一次位置指令为 1280 脉冲。完成判定仍是估计运动时间加停稳时间，共 840 ms；单次转位超时 2 秒。**目前没有电机到位反馈**，UART 发送成功不能证明实际转盘到位，实车需确认正反向各一次恰好移动一个槽且不会失步。
- 库存仅在 RAM 中。断电或主控复位后按空盘重新开始；不要带球复位后继续旧任务。取消、通信故障、转位失败后保留库存并标记“不确定”，链路复位不会清除这项标记。恢复时人工清空转盘、对准槽口、复位主控，再开始新任务。
- 正常入库结束、库存全空后可以开始新一轮。单独执行圆盘任务后转盘有球，不能直接重启新 PATH/DISC 来清掉记录。

## 增量部署

主控固件与 RDK 桥接程序需要配套更新。RDK 只需上传 `tools/rdk_stm32_bridge.py`，视觉 ROI、HSV、任务尺寸等配置保持原文件。

Windows PowerShell 直接执行，无需先 SSH 登录：

```powershell
cd "F:\licang2026\2026ROBOCUP-ZHY\2026ROBOCUP-ZHY\RDK"
scp .\tools\rdk_stm32_bridge.py sunrise@192.168.128.10:/home/sunrise/Desktop/rdk_stm32_bridge.py
```

RDK 远程桌面终端（沿用现有目录 `~/licang_vision` 和服务 `rdk-disc.service`；任务未运行时更新）：

```bash
cd ~/licang_vision
sudo systemctl stop rdk-disc.service
cp -a tools/rdk_stm32_bridge.py "tools/rdk_stm32_bridge.py.bak-$(date +%Y%m%d-%H%M%S)"
python3 -m py_compile ~/Desktop/rdk_stm32_bridge.py
```

无报错后安装并启动：

```bash
cp ~/Desktop/rdk_stm32_bridge.py tools/rdk_stm32_bridge.py
sudo systemctl start rdk-disc.service
journalctl -u rdk-disc.service -n 50 -f -o cat
```

主控编译产物：`build/Release-Path/chassis_motor.elf`。本次 RFID 回退仅修改主控；如 RDK 已上传支持 G109/G110/G111 的桥接程序，无需再次上传。回退版编译后还需重新烧录主控。

## 调试与验收

以下为主控调试器可查看的 `path_diagnostics` 字段，不是新增串口文本指令：

| 字段 | 含义 |
| --- | --- |
| `rfid_count` | 本轮历史采集数，入库后不减少 |
| `inventory_occupied` | 12 位占用掩码，第 0 位对应逻辑槽 0 |
| `inventory_slot` | 当前对准存取口的逻辑槽，0～11 |
| `inventory_uncertain` | 非零时禁止自动重新开始 |
| `warehouse_code` | 当前列行编号，以十六进制显示；0x23 的十进制显示是 35 |
| `warehouse_placed` | 已收到放置动作完成回包的球数 |
| `inventory_fault` | 位标志：1=缺少组合块数据；2=块数据非法；4=编号/UID 冲突；8=当前槽已满；16=转位错误 |

`inventory_fault` 在前三个任务只作附加诊断，不改变原来的 UID 确认；转位失败还会标记槽位不确定，仓库阶段拒绝按不确定位置取球。`PathPorts_CopyInventory()` 可读取完整槽位表。放球成功目前依据动作组完成回包，不包含“球已实际脱离夹爪”的传感器确认。

首次实车可先用一个编号 23 的球验证：采集后只转一次；第一、第二列只移动不放球；第三列只执行 G110，随后结束。之后测试乱序采集九球，确认每列按第一行、第二行、第三行放置。

```powershell
cmake --build build/host-path
ctest --test-dir build/host-path --output-on-failure
python -m unittest discover -s RDK/tests
cmake --build build/Release-Path
```
