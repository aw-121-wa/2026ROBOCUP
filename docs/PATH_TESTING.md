# PATH 联调与安全检查

本次迁移以旧工程 `snapshot-2026-08-24-servo-arm` 的实际执行代码为流程依据。
机械臂动作组仍存于舵机控制器，由 RDK 调用；STM32 不再直接连接舵机控制器。

## 接线（沿用旧工程）

| 用途 | STM32 接口 | 波特率 |
| --- | --- | --- |
| RDK 通信 | UART4，PC10 TX / PC11 RX | 115200 |
| VOFA 与用户命令 | UART5，PC12 TX / PD2 RX | 115200 |
| RFID | UART8，PE1 TX / PE0 RX | 115200 |
| 存球转盘，电机地址 5 | USART6，PC6 TX / PC7 RX | 115200 |
| 底盘四轮 | USART3，保持当前配置 | 921600 |
| IMU | USART2，保持当前配置 | 9600 |

TTL 串口交叉连接 TX/RX 并共地，不把 RS-232 电平直接接到 MCU。
灰度传感器沿用 PD8、PD0、PD1、PD3，低电平表示在线；圆柱红外沿用 PD10，低电平表示检测到。
转盘沿用每格 1280 脉冲、100 rpm、顺时针存球，卸球反向转位。
旧实现根据运动时间与稳定余量判断转位结束，并非编码器反馈证明已到位。

## 启动约定

配套上位机部署见 [RDK 说明](../tools/rdk/README.md)。新增固件输出目录为 `build/PATH-Release`，不要误烧旧目录中的固件。
需要自行重编译时，在本工程根目录执行：

```powershell
cmake -S . -B build/PATH-Release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake
cmake --build build/PATH-Release
```

确认机械机构安全后，DAPLink/OpenOCD 烧录命令为：

```powershell
openocd -f interface/cmsis-dap.cfg -f target/stm32f7x.cfg -c "program build/PATH-Release/chassis_motor.elf verify reset exit"
```

以上是供用户执行的指令，开发过程中没有连接或烧录硬件。

1. 先使上位机配套程序就绪，确认摄像头和舵机串口设备名。不能继续使用只支持整批 DISC_START 的旧桥接程序。
2. 车身保持静止，等待 IMU 校准完成；先发送 `ARM` 加换行。
3. 确认已解锁且没有故障后，发送 `PATH` 加换行。固件先与上位机握手，等待 G0 准备姿态完成，再开始行驶。
4. `STOP` 加换行用于取消流程。机械臂若正在执行完整动作组，软件取消不等同于瞬间切断舵机动作。
5. 不在完整路线尚未逐段验证时直接落地运行 PATH。保留可立即断开执行器电源的人工急停手段。

## VOFA 任务诊断

默认完整遥测保留原通道 0..26，追加：

| 通道（从 0 开始） | 内容 |
| --- | --- |
| 27 | PATH 状态：0 待机，1 执行中，2 完成，3 取消，4 超时，5 错误 |
| 28 | 当前路线步骤，0..12，对照下方路线 |
| 29 | 本轮圆盘已接受的不同 RFID ID 数量 |
| 30 | 任务接口故障位，0 表示无接口故障；还需检查原底盘故障通道 15 |

若关闭完整 IMU 遥测，追加通道为 22..25。通道 16 仍是主机指令处理结果，1 表示接受，不代表 PATH 完成。
调试器中 `path_diagnostics` 还包含子阶段 phase、ID 位图、链路回复、转盘回复及会话序号。
任务状态 3/4/5 不表示机械臂已经安全停妥；在上位机当前动作完成回复之前，新的运动仍需被互锁。

## 圆盘完成与超时

G101 架起摄像头，识别目标色后执行完整 G102，动作组不拆分。
以 RFID 的本轮有效 ID 为计数依据，不以执行 G102 的次数作为球数。
同一个 ID 重复上报不重复计数或转位；第五颗球也完成一次转位后才完成圆盘阶段。

`App/disc_task_config.h` 的 `DISC_TASK_TIMEOUT_MS` 默认 20000 毫秒。
从圆盘阶段启动计时，读到 ID 不重置总计时。
超时禁止新抓取，并与当前动作的安全结束区分；超时不是抓满成功。
第五个 ID 若已在截止前确认，允许最后一格转位在截止后完成，随后正常完成圆盘阶段。

固件启动时从硬件 RNG 生成会话编号，只配置独立 PLLSAI 的 48 MHz 输出，不改变主 PLL、底盘控制时钟或串口时钟。
随机数或任务串口初始化失败时拒绝 PATH，不使用固定编号继续执行。上位机发生机械臂完成反馈错误时会保持错误锁定；先人工确认机构停止，再重启两端、重新校准和 ARM，不能盲目重复 PATH。

## 建议验证顺序

1. 断开电机动力，只验证命令解析：未 ARM 的 PATH 必须拒绝；重复 PATH 不得重启任务；STOP 后不得自行执行剩余步骤。
2. 独立检查传感器电平及 RFID 实际字节：旧 RFID 协议是数值字节 0x01..0x09，不是 ASCII 字符 '1'..'9'。
3. 转盘清空后检查一格的方向、角度和停止，确认机械机构与旧脉冲配置一致。
4. 底盘架空检查任务发出的前进、横移、旋转方向；架空不验证距离和灰度找线。
5. 机械臂留足活动空间，检查准备动作、单次抓放、RFID 计数、转盘联动与下一次抓取的互锁。
6. 连续重复同一 ID，应只计一次；输入五个不同 ID，应计五次并完成最后一格。
7. 不提供足够 ID，验证 20 秒总超时与当前动作收尾；断开上位机、遮挡相机、模拟错误回复，均不得让底盘继续下一段。
8. 场地清空并有人值守，最后才逐段、全程验证实际路线。

## 路线核对

左前 20 度 1800 mm → 前进 2300 mm → 逆时针 178 度 → 圆盘任务
→ 逆时针 178 度 → 后退 1810 mm → 圆柱任务 → G0
→ 前进 330 mm → 楼梯任务 → G0 → 左移 1650 mm → 入库任务。

圆柱段以累计旋转 352 度完成，最多抓取四次；楼梯沿用 Part3 → Part2 → Part1。
真实场地图像、抓取姿态和路线距离仍需要实车验证，编译和模拟测试不能替代这些检查。
