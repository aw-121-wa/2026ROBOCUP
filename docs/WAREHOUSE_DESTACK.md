# 仓库倒垛

## 流程与开关

带视觉固件默认 `PATH_DESTACK_ENABLE=1`。`PATH_VISION_ENABLE=0` 的纯底盘路线不执行倒垛。可编译时设置 `-DPATH_DESTACK_ENABLE=0` 恢复原放球流程。

先按原入场动作扫描三列底部序号、记录停车位置。第一列识别失败继续使用原默认123策略，第三列身份可由前两列推断，位置仍按200 mm建立。此阶段不夹块、不放球。

随后物理列3→2→1，每列从上到下检查；夹到方块后前往第三列外侧200 mm的第四列，按方块数字放到对应行，再返回原列继续检查。整列检查完才按现有库存逻辑放球。第一列完成后回到第三列记录位置，接原返程路线。

| 行 | 识别姿态 | 夹取 | 放置 |
|---|---|---|---|
| 3（最上） | 112 | 113 | 114 |
| 2 | 115 | 116 | 117 |
| 1（最下） | 118 | 119 | 120 |

夹取按来源行、放置按数字选择。所有动作等待完成回包再移动。第四列占用按本次任务记录，开始时应为空；重复目标行报错，不覆盖。位置基于现有开环积分，不是编码器位置反馈。

## 视觉标定（目前尚未完成）

底部数字相机继续识别仓库列号；球摄像头用于方块。新文件 `RDK/rdk_vision/block_digits.yaml` 分红蓝侧、行号配置ROI、数字样本和空仓参考。默认所有行 `calibrated: false`：返回UNKNOWN并停稳重试，不会把未识别当空仓。

每侧、每行使用对应动作112/115/118，在实际识别位置采集：空仓、数字1、2、3的640×480球摄像头完整图像。ROI应只包含当前格子的数字面/空仓区域，不包含邻格数字。每个数字还需指定只包住印刷数字的紧边界矩形。不要用底部相机旧模板冒充方块相机样本。

从RDK工程目录导入样本（以下坐标仅演示格式，必须按实拍画面确定）：

```bash
python3 tools/calibrate_block_digits.py --side red --row 3 --input /tmp/empty.png --label empty --roi 160 100 320 280
python3 tools/calibrate_block_digits.py --side red --row 3 --input /tmp/one.png --label 1 --glyph 220 170 40 90
# 同样导入2、3，然后验证这四张标记图：
python3 tools/calibrate_block_digits.py --side red --row 3 --enable
```

每次更新样本自动清除该行启用标志。`--enable` 检查四张标记图并启用该行，仅代表离线样本通过；还须在三列、不同光照和遮挡条件下验证。每行/每侧都需要独立样本。实际拍照或运行机械臂前应结束当前任务，避免同时占用球摄像头。

明确数字需3个不同的新鲜帧一致；空仓需正向匹配空仓参考，至少10帧且持续0.5秒。黑帧、遮挡、过期帧、多个数字、缺失样本均不能当空仓。相机异常为ERROR，正常图像但无法确定为UNKNOWN。

## 协议与遥测

- STM32发送 `BLOCK_CHECK <token> <row>`，RDK回复 `BLOCK_RESULT <token> <value>`。
- value：0未知、1/2/3数字、4确认空仓、5故障；只接受当前请求标记。旧回包及底部列号回包不能完成方块检查。
- 未知停稳重试；故障停止。夹取/放置和移动各保留30秒限时；数字检查10秒通信限时。
- 遥测phase：32识别姿态、33识别、34夹取、35去第四列、36放置、37返回原列、38去上一列、39回第三列接返程。
- 开始新任务清空持块/第四列占用状态。夹取后故障需要人工处理持块和实际位置，不能直接重发PATH当作已复位。

## 构建与部署

主机：`cmake --build build/host-path -j4`，`ctest --test-dir build/host-path --output-on-failure`。
固件：`cmake --build build/Release-Size-Audit -j4`。
RDK：新 `block_digits.py`、`block_digits.yaml`、样本目录，以及更新的 `tools/rdk_stm32_bridge.py` 必须一起部署。桥接代码更新需重启服务。旧RDK不识别BLOCK_CHECK，不能与新倒垛固件混跑。

本次代码没有自动部署、烧录或实跑。未标定时不能宣称方块视觉已可用。
