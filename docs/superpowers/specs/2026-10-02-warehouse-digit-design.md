# 仓库底部数字识别与放球设计

## 已确认需求

两路 USB 摄像头均接现有 RDK X5。球摄像头沿用原有圆盘、绕桩、阶梯识别流程。新增的数字摄像头朝向仓库正面，一次只能看见一个数字。数字只用于判断到位停车和货位列号，不做像素测距、位置微调或视觉角度校准。

数字为 1、2、3，标在第一行货位正下方；该数字定义整列的逻辑列号。球 RFID 高半字节仍为行号，低半字节为逻辑列号，机械臂 GROUP 109/110/111 仍对应三行。第一物理列识别失败时，本次整个仓库阶段锁定默认模式，物理第一、第二、第三列分别使用 1、2、3，后续数字结果不再改变顺序。

## 工作流程

1. 仓库第一列沿用原入场找线和航向保持，在进入放球前读取当前数字。后两列保留原 200 mm 移动作为识别失败时的到位后备。
2. 后两列移动期间开启数字识别。离开上一列的数字后才能接受新的识别结果，避免同一块标牌重复触发停车。有效识别触发 PC_HOLD，等待底盘停稳，再完成原灰度到位检查和地图 0° 航向检查。
3. 第一列停车后进行有界识别；没有可信结果或数字相机无法打开，则锁定默认模式，后两列直接沿用原 200 mm 移动和原放球逻辑，不再请求数字识别。第一列成功则锁定数字模式，后续列继续识别，不以默认列号混合投放；超时沿用停止机制，保留尚未投放的库存。
4. 一列的数字一经确定，在该列全部放球动作期间保持不变。RFID 匹配使用该数字和原行号。转盘规划使用已确认的逻辑列号，未知的后续列暂按默认列号估算；确认下一列后重新规划未完成部分。
5. 放完该列才允许下一次数字识别。球库存只在原机械臂成功回包后删除。机械臂运行期间不接受数字触发移动，也不切换列号。

## 识别与通信

- 两路摄像头使用各自设备路径和配置；部署时使用 /dev/v4l/by-id 或 /dev/v4l/by-path 的稳定路径，不假定 /dev/video0 与 /dev/video2 永远对应同一相机。
- 数字识别限制在仓库底部 ROI，过滤背景与边缘截断目标，匹配 1/2/3。连续至少三个不同的新鲜帧给出一致结果才有效；重复消费同一帧不累计确认次数。
- 没有现场图像时，字体模板按规则参考字体初始化。现场需验证 ROI、最小置信度及识别速度，不能把主机合成图测试等同于实际摄像头准确率。
- 请求带当前物理列号与本次任务标记；回复回显标记并包含识别数字或未识别。只接受当前请求对应的新结果，忽略过期结果。数字回包与现有机械臂、球识别回包分开处理。
- 第一列数字相机异常和未识别进入整次仓库默认模式。数字模式中后续识别失败不静默切换到默认顺序。STM32/RDK 主链路断开、底盘故障、机械臂失败仍保留原停止机制。

## 模式锁定

第一列有可信数字则进入数字模式；第一列无可信数字则进入默认模式。每次 PATH 开始清除模式，进入仓库第一列后只决定一次。默认模式忽略后续数字，不混合映射。数字模式只接受 1/2/3 且不重复使用逻辑列号；后续识别超时不猜测默认列号，保留原超时停止机制。

## 改动范围

- RDK：新增数字识别模块、独立相机配置与桥接命令；保留现有球识别参数和动作组。
- STM32：扩展 RDK 数字回复接口及仓库状态机；保留阶梯、绕桩、开局、回家路线和控制器参数。
- 测试：数字多帧确认、失效/重复帧、旧请求回包、移动中停车、停稳后放球、列号洗牌、默认 123 回退、取消与相机异常。
- 构建：执行主机测试、RDK Python 测试和 Release LTO 编译。当前任务没有授权本次烧录或启动跑车，因此部署与实车验证单独报告。

## 验收

顺序 3/1/2 时，RFID 0x23 的球在物理第一列第二行投放；第一列无数字时全程按物理 1/2/3 投放，后续数字不能改变该模式。移动中确认数字会先停车，底盘未停稳或航向未满足要求时不允许发放球动作。旧数字、旧相机帧、当前机械臂动作期间的数字不会触发下一列。
